## 2025-02-18 - Missing Password Length Validation During Registration
**Vulnerability:** The backend registration endpoint (`/api/register`) did not enforce any minimum password length or complexity rules. A user could register an account with a password of length 1 (or even 0), making accounts trivially susceptible to brute-force attacks and severely undermining authentication security.
**Learning:** The assumption that frontend validation (or lack thereof) is sufficient for password security is dangerous. Security rules must always be enforced at the API layer, as clients can bypass frontend checks. The codebase explicitly documented that "The API sets no password length or complexity rules", highlighting a known but unmitigated risk.
**Prevention:** Always implement strong input validation on the server side for sensitive fields like passwords. Establish a baseline password policy (e.g., minimum 8 characters) at the API level and mirror it in the frontend UI for better UX. When writing security tests, ensure that mock data (like `"password": "1"`) does not inadvertently bypass or conflict with intended security rules.
